如果你想看这个插件为什么要这么设计，可以先读这篇：[给文章里的 Emoji 换一套表情](/post/rehype-fluent-emoji)。

## 为什么要测

这篇文章不是为了把页面变成表情包墙 😀，而是想检查一件很具体的事：当 MDX 正常写作时，段落里的 emoji 能不能被替换成 Fluent Emoji 图片，同时不影响中文排版、链接、代码块和列表。

如果一切顺利，像火花 ✨、火苗 🔥、火箭 🚀、彩虹 🌈 这些符号会变成统一风格的小图标；但句子仍然应该先是句子，而不是一串会跳出来抢戏的装饰。

## 一天的测试笔记

早上先泡一杯咖啡 ☕，打开电脑 💻，给今天的任务列一个小清单 📝。我想象这个流程像一次轻量巡航：先用放大镜看看内容管线 🔍，再拆一个小拼图 🧩，最后把可疑的边角都收进盒子 📦。

真正写配置时，心情大概是这样：看到插件挂上去会微笑 🙂，看到第一颗 emoji 变成 Fluent 风格会想点个赞 👍，看到 CSS 没把它撑成巨大的文章图片，就可以放心说一句：好，今天没有白忙 ✅。

## 多一点密度

下面故意把 emoji 密度调高一点，但仍然保留可读文字：

- 设计检查：颜色 🎨、节奏 🎧、层级 📚、一点点星光 ✨。
- 工程检查：构建 🛠️、测试 🧪、搜索 🔍、记录 📝。
- 体验检查：不要太吵 😀，不要太挤 🙂，也不要让每个段落都像在开派对 🎉。
- 内容检查：有火 🔥，有心 ❤️，有方向 🧭，但文字还是主角。

再来一段连续场景：我在夜里 🌙 打开预览，看到标题旁边的火箭 🚀、段落里的彩虹 🌈、列表里的书 📚 和咖啡 ☕ 都乖乖站在基线上。它们没有挤压行高，也没有触发图片画廊的交互，像一批刚刚训练好的小型 UI 配件。

## 代码块应该保持原样

代码里的 emoji 不应该被替换。下面这段如果仍然显示原生字符，就说明插件跳过了 code/pre 路径：

```ts
const status = 'build passed ✅'
const mood = 'ship it 🚀'
```

## 收尾

这篇测试文的目标很简单：让 Fluent Emoji 在真实文章环境里露个脸 👋🏻。如果它能安静地增强文本，而不是破坏阅读，那么这条 MDX 管线就算通过第一轮验收了 ✅✨。
